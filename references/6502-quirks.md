# 6502 语义陷阱全表

SKILL.md 的 §6.5 给的是一张八行的速查表，本文是它的全表：把复刻过程中真正咬过人的 6502 语义陷阱逐条展开，每条四段——**现象**（在成品上看到什么）、**6502 语义**（原机为什么是这个行为）、**翻译要点**（翻成目标语言时的动作）、**实例与证据**（回查地址与出处）。

案例来自一次完整的 NES 复刻项目的机器验证记录（下称"某项目"）。所有行号、字节值、地址都在落笔前回 ROM 与反汇编逐条复核过；凡与二手记录不符之处，一律以 ROM/反汇编为准，并已在条目中就地标出。反汇编引用写成 `Bank7.ASM:355-391` 这样的相对形式，"回查"指向该项目的任务报告名。

先约定三处口径，避免和既有文档打架：计数 0 的含义**以载体例程的分支为准**，与同目录的 `extraction-playbook.md` §4.2 完全一致（那里讲的是"图案链与 nametable 流两套解码器不能互换"）；进位链、定点、A 寄存器约定的表述与 SKILL.md §6.4 一致；一址多义与死代码分别衔接 §6.1、§6.6 的纪律。编号 1-15 与任务清单同序，16-17 是写作中复盘追加的两条。

## 逐条展开

### 1. 计数 0 按 256

**现象**：数据比预期短 256 字节，或某个"长度 0"的条目整段消失；换一段数据又一切正常——只在恰好用到 0 这个编码时才显形，极难查。

**6502 语义**：`DEC $04 / BNE -` 是"先减后判"的循环骨架，计数 0 先减成 $FF、非零成立，于是循环整个 256 次。而"先比较后退出"的骨架（`CPY / BEQ`）在 0 时走另一个出口，甚至把 0 解释成"拷贝到回绕才停"。计数 0 等于什么，**由例程里的循环结构决定，没有全局答案**。

**翻译要点**：逐例程读循环骨架再决定。`DEC/BNE` 收尾的循环翻译成先减后判的 do-while 形式（0 即 256）；用比较和相等跳出收尾的循环，翻译成"计数就是循环体次数"（0 即不执行，或按原码落进哪个出口就落进哪个）。这两者在 0 之外完全等价，只在 0 编码上分叉，因此必须对着骨架写注释。

**实例与证据**：图案链 `subLoadNewPatternTable`（`Bank7.ASM:355-391`）的两个分支都以 `DEC $04 / BNE` 收尾（字面分支 :379-380、重复分支 :389-390），计数 0（控制字节 `$80`/`$00`）都是 256，提取侧按 256 实现（回查 task-1.2-report，`test_count_zero_means_256`）。同一 ROM 的 nametable 流 `Label925`（`Bank7.ASM:2411-2443`）不同：字面分支用 `CPY $02 / BEQ`（:2426-2427），计数 0 走成"拷贝 255 字节、指针只推进 1"——`$80` 在这个流里是坏编码，遇到应当报错而不是猜一个数；只有它的重复分支（:2439-2441 `DEY / BNE`）保持 0 按 256。这个不对称在提取器里留了案（回查 task-2.4-report"留待后续"），并在 `extraction-playbook.md` §4.2 定稿。**同一个"计数 0"，在同一个 ROM 里可以有两种含义**——这就是本节口径的来源。

### 2. CLC/BCS 进位链隔断

**现象**：多段加法拼出的坐标算完后，页选择（高字节、$0300/$0400 页、上下半图）与预期全反；按"全程累加、总和进位"实现，某些移动方向上整类对象选错页。

**6502 语义**：`ADC` 的进位是单次运算的输出。链式加法里每插一个 `CLC`，就把上一段的进位丢掉；作者写出的 `CLC / ADC $16 / CLC / ADC Scroll` 意味着最后那条 `BCC/BCS` **只看最后一次** ADC 的进位，整体是多次模 256 相加，而不是"一个 16 位总和"。

**翻译要点**：不要用 32/16 位整数一次算总和对 $100 取进位。把每一步按 `(a + b) & 0xFF` 逐次取模，进位只取末次的 carry；在代码注释里写下 ASM 行号——这类"看起来等价"的实现差异，会被后续的顺手优化悄悄改回去。

**实例与证据**：横向碰撞页选择 `fctGetCollisionTypeFromRAM300_4FF`（`Bank7.ASM:4482-4492`）：`SubPixel + SpeedLB → Pos ADC SpeedUB → CLC ADC $16 → CLC ADC Scroll`，:4492 的 `BCC +` 选 `$0300`/`$0400` 页只看末次进位。初版按累加总和判页，在 Left 移动场景（低位相加产生进位、被第二个 `CLC` 吃掉）错选页，水花锚定用例当场抓住（回查 task-3.6-report）。第二例在直升飞机相对吉普定位 `subSpawnPlane_HeliPositionRelativeToJeep`（`Bank7.ASM:6823-6828`，`CLC ADC $00 / CLC ADC $40`）：$C0+$E0 的结果是 $A0、页不进位，测试初稿按总和判 UB=1 判错（回查 task-4.11-report）。

### 3. 16 位借位链判在屏

**现象**：用单字节比较（`LB >= Scroll`）判"对象是否在屏内"，UB=1（绝对坐标 $100-$1FF）的对象两种情形**全反**：LB 小于滚动值的（右半图的大门、建筑）被标成屏外——不可见、不可击中、不开火；LB 大于滚动值的（越出右缘的）反被标在屏。

**6502 语义**：绝对坐标是 16 位。`LB - Scroll` 之后还要 `UB SBC #$00` 把借位传播到高字节；只有结果 `== 0` 才意味着 `0 ≤ LB-Scroll < 256`（落在当前屏页内），非 0（无论 $FF 还是 1）都在屏外。单字节比较丢掉了高位，UB=1 时结论整体翻转。

**翻译要点**：翻成显式借位链——`noBorrow = (lb >= scroll); a = ub - (noBorrow ? 0 : 1); if (a == 0)` 才算在屏，在屏位置取 `lb - scroll`，并把状态字节的屏外位（见条目 17）一并处理。前置门（纵向 UB 为 0、横向 UB < 2 的快速剪枝）也要照抄，它们是原码的一部分而不是可省的提前返回。

**实例与证据**：`subUpdateSpritePositionForScrolling`（`Bank7.ASM:1667-1686`）：:1672-1674 `LDA LB / SEC / SBC Scroll / STA $00`，:1676-1678 `LDA UB / SBC #$00 / BNE ++`（屏外分支），:1679-1683 屏内写位置并清状态 bit7。这是某项目"大门炸不开"一轮排查的根因（UB=1 的 $160 大门被误标屏外），修复后新增锚 `horiz_visibility_ub1_borrow_chain`（$E0/$FF 恰在屏、$100/$140 越界）以及端到端"手雷/火箭筒破门"两用例（回查 2026-07-22 修复记录·第三轮试玩）。

### 4. 定点积分链与 LSR/ROR 半速

**现象**：速度或位移只对一半——慢了一半或翻了倍；或者"大体对、跑久了漂移"。把"亚像素 + 像素"当成一个 16 位整数一次相加，会在进位与半速两个地方与原码分叉。

**6502 语义**：位置是 `{整数 LB, 亚像素 SubPixel}` 的两字节结构：`SubPixel += SpeedLB`（进位丢掉），`Position ADC SpeedUB`（把上一步的进位带进来，见条目 2 的注意）。"半速"不是除法，而是对 16 位量整体右移一位：`LSR UB / ROR LB`，UB 的最低位进 LB 的 bit7，得到"每帧半像素"；负方向不能移位（有符号的算术问题），原码改为直接给 LB 装 $80。

**翻译要点**：保持两字节结构（亚像素与整数分开存），逐字节加、进位显式传递；半速写成对 16 位量 `>> 1` 或逐字节 `LSR/ROR`，不要写成"整数除 2"了事（两者在负值与余数上不同）。有符号/无符号照抄原码的分支（`BPL`/`BMI` 就是符号判断，别用目标语言的默认整数类型兜底）。

**实例与证据**：`Label1186`（`Bank7.ASM:5528-5637`）：水域半速在 :5561-5574（UB 为负 → `LB = $80` 直置；否则 `LSR UB / ROR LB`，纵横两轴各一份），定点积分链在 :5604-5621（`SubPixel += SpeedLB`、`Position ADC SpeedUB`、双写屏幕与逻辑位置）。锚 `water_half_speed_and_splash` 断言 `UB 1→0、LB 0→$80`、两帧走 1 像素（回查 task-3.6-report）。

### 5. 先减后判：DEC 后判值

**现象**：状态机"到位"判定早一帧或晚一帧；按"DEC 前的值"布置测试，行为对不上——要么推进早了一轮，要么永远不推进。

**6502 语义**：`DEC Addr / LDA Addr / CMP #$XX / BEQ` 里比较的是**递减之后**的值。写"DEC 到 $C0 才推进"的原码，实际进入条件是 $C1：DEC 之后才是 $C0。

**翻译要点**：把"计到某值触发"的条件一律翻成对递减后值的判断；测试与锚点按"进入值 = 触发值 + 1"布置，并把这条推导写进测试名或注释——否则下一个人会按直觉改成"进入值 = 触发值"，测试就失去抓 bug 的能力。

**实例与证据**：SpreadTurret 升起段 `SpreadTurretState1`（`Bank6.ASM:2596-2611`）：`DEC SpriteData1,X / LDA / CMP #$C0 / BEQ`（:2607-2611 推进状态），另有 :2599-2605 的字形递增（跳过条件含"当前值 == $C0"）。锚点布置用 DEC 前 $C1（DEC 后 $C0 才推进）、&$0F==0 的路径用 $F1（DEC 后 $F0），初版按 $C0 布置落进错误分支（回查 task-4.8-report）。同一模式在 MobileInfantry State6 的恢复分支（`Bank6.ASM:525-532`，`DEC SpriteData8,X / CMP #$F9`，即原值 $FA 进入）也有（回查 task-4.3-report）。

### 6. 隐式 A=0 依赖

**现象**：例程一进就行为异常——本该被清零的变量保持旧值；反读源码，"这个 `STA` 之前没有任何 `LDA`"，看着像漏了。

**6502 语义**：A 是跨过程传递的隐式返回值。`subSetPPUToBlackScreen` 以 `LDA #$00 / STA PPUADDR / STA PPUADDR / STA PPUMASK` 收尾，返回时 A=0 是**约定**；调用点紧接着连写若干个"要清零"的变量，不再前置 `LDA`。反汇编注释也明写"（A is ZERO from this jsr）"。

**翻译要点**：把这个约定显式展开为 0（或让函数显式返回该值），并在注释里写明"原机借 A=0 的约定"。目标语言没有"寄存器遗留值"这个概念，静默丢掉会让后续变量停在旧值——症状是"程序能跑、数值偶尔诡异"，与地址错（SKILL.md §6.1）同类的难查。

**实例与证据**：`Bank7.ASM:240-249` 例程本体与三处调用点：:312-314（`JSR subSetPPUToBlackScreen ;A is ZERO from this jsr` 后连写两个 STA）、:2393-2399（进入 `Label925` 时清五个变量）、:8354/:8390（注释 "A must be 0 here"）。C 侧在 loader.c 显式展开并留注释（回查 task-2.5-report"语义备忘"）。

### 7. 尾调用 RTS：借道返回

**现象**：处理完一个对象后，循环里剩下的对象被整段跳过；或者相反，本该收工的地方又跑了一遍。两个都"看着像 return"的出口，实测行为不同。

**6502 语义**：`JMP subX` 与 `JSR subX` 的差别在栈上有没有返回地址。尾调用 `JMP` 进子例程后，子例程的 `RTS` 弹出的是**调用本例程的那个人**的返回地址——于是"处理完这个对象就整体收工"。同一段代码里还混着另一种写法：`JMP` 回跳到匿名标签，那是"继续循环、处理下一个对象"。两者语义不同，不能都翻成 return。

**翻译要点**：把"最后一条指令是 `JMP subX`"的出口翻成直接调用 + 返回（`subX(); return;`）；把回跳匿名标签的出口翻成继续循环（`continue` 或裸循环）。每个出口都问一句"这里的 RTS 会回到谁"，答案写在注释里。

**实例与证据**：`Label1005` 的 POW 分支（`Bank7.ASM:4864`，`+++: JMP subDespawnSprite`）是尾调用：despawn 的 RTS 直接返回 Label1005 的调用者，**第二个吉普不再参与本帧判定**；同例程的星类/helipad 分支末尾是 `JMP --`（:4826-4829，`--: DEY / BMI ++++ / JMP ---`），继续 Y 循环处理下一个吉普。两者在 C 侧分别翻成 return 与继续循环（回查 task-3.8-report）。

### 8. 无入口死代码

**现象**：一段代码读起来逻辑自洽（清速度 → 播旋转动画 → 推进状态），却找不到任何入口；顺手翻译了，会凭空多出一个永不执行的分支，还可能在错误的时机占位。

**6502 语义**：没有任何 `JSR`/`JMP`/分支/dw 表指向的代码段，是反汇编的线性残留（改版后留下的孤儿），行为上等价于不存在。

**翻译要点**：不翻译，但**要记录**（位置、判定依据、结论）——判定可能是错的（间接跳转表抵达的路径静态搜索看不到），留档才有机会纠正（衔接 SKILL.md §6.6）。判定用交叉引用扫描（全 bank 扫调用指令的目标地址与 dw 表引用，再解匿名标签），不能凭"看着像没用"。**死段边界按引用点切**，不按"看起来连续"切——与死段物理相邻的匿名标签或具名标签常常是活的。

**实例与证据**：`subRotateJeepTowardsDirectionOfMotion` 的 RTS（`Bank7.ASM:5780`）之后、`JeepCollisionState`（:5809）之前的片段：:5781-5786（清速度/置计时/INC 状态）与 :5788-5805（旋转动画自闭环）无入口；但夹在中间的 `--:`（:5787，`JMP Label1186`）被 :5853、:5866 引用，末尾的 `Label1202:`（:5806）被 :5849、:5864 引用——都活着，按 :5781-5786 ∪ :5788-5805 切除。（回查 task-3.6-report；其口径" :5781-5807 整体死代码"是范围标粗，本表按引用点修正边界。）另有两类指令级死路径：白弹炮塔 `Bank6.ASM:6785-6788` 的 `JSR subUpdateSpriteForDirectionChange / TYA / LDA SpriteData6,X / LDA #$0D`——`TYA` 的结果被下一条 `LDA` 覆盖（黄弹同位置 :6970-6972 是 `TYA / STA SpriteData6,X` 正常写入），Data6 保持生成值，翻译时按 ASM 区分、不要"修好"它（回查 task-4.4-report）；`Bank6.ASM:6511-6516` 的 `LSR / BCC +` 两个去向是同一行，LSR 的结果被丢弃、分支恒等，照译成空操作并留注释（回查 task-4.11-report）。

### 9. 立即数与 RAM 地址同形

**现象**：边界钳位的取值看起来像"读变量 $40"，实际是常量 $40；按读变量翻，边界的表现随该变量的残留值漂移——某项目里表现为"吉普瞬移到屏幕右缘"。

**6502 语义**：`LDA #$40`（立即数）与 `LDA $40`（读零页 RAM $40）只差一个 `#`，而注释、报告甚至同一段代码的相邻行都写成 `$40` 这种同形数字。更巧的是，这类撞号在原码里并非偶然：与常量对照的那个变量地址，常常就是常量值本身。

**翻译要点**：把 `#` 当成翻译时第一等重要的符号，逐字确认每条 `LDA/ADC/SBC` 的操作数是立即数还是地址。边界钳位翻成常量赋值（`x = 0x40`），不要翻成"读另一个字段"；发现同形数字时，回读上下文（`BCC/BCS` 的分支语义、钳位的意图）消歧，并把判断写进注释。

**实例与证据**：`Label1096` 的左界处理（`Bank7.ASM:5175-5196`）：`LDA $40（变量）/ BNE Label1136` 与 `Label1136: DEC $40 / LDA #$40（立即数）/ STA JeepHorizPosition,X` 同一个 `$40` 两种身份；而边界常量 `JeepMinimumHorizontalPositionForScrolling = $40`（`JeepAttributes.ASM:33-36`），撞的正是那个变量地址。初版按变量翻，$40 的残留值把吉普钳到屏幕右缘（用户报告的"左界瞬移"），改为常量后消失，C 侧注释记作":5183 LDA #$40 立即数 quirk"（回查 2026-07-22 修复记录·第二轮）。

### 10. 一址多义

**现象**：某个字段在不同时刻含义不同。合并成一个字段后行为错乱——子弹"永远不死"、分数显示串进移动方向、关卡过渡走错分支。

**6502 语义**：RAM 是扁平的，作者按"这个对象是这种类型时，这个字节就在这个角色"复用地址；符号表给一个名字，另一处子系统直接按另一个名字用，没有硬件约束，纯看代码路径。

**翻译要点**：按状态/时机分语义（SKILL.md §6.1）：要么 union 显式表达，要么按状态给不同名字，并在注释里写"此时它是哪个角色"。测试布置尤其要注意：把"寿命"字段当"目标吉普"预置成 0，会让"DEC 到 0 才结束"的循环永远不成立。

**实例与证据**：`$06E0` 至少三义——`SpriteWhichJeeptoAttack`（`RAM_Symbols.ASM:1912`；位 0-6 是"换目标的计时"、bit7 是"打 2P"，读法见 `Bank7.ASM:6808-6814`）在敌弹上是寿命（`Bank6.ASM:7643-7646` 生成时写入、:7672-7674 `DEC $06E0,X / BEQ` 击地），在 L6 终 boss 火焰上是"喷出计时"（`Bank6.ASM:3626` 注释 + :3638）（回查 task-4.3-report）。`$00D8` 的 `JeepMovementDirection` 同时是分数显示的 tile 缓冲（`RAM_Symbols.ASM:250` 自注 "Also used for displaying score/xp"，C 侧翻成局部数组并保留同址注释）（回查 task-3.3-report）。`$0050` 的 `JeepMainWeapon` / `Jeep1MainWeapon`（`RAM_Symbols.ASM:87-88`）在标题/剧情态是 POW 肖像的滚动位置（`Bank7.ASM:1159` 注释 "reused RAM location for POW screen. Scroll position"），关卡过渡态又回到武器语义（`Bank7.ASM:917`，GCS7 的首个分支）（回查 task-6.3-report）。

### 11. 输入同步覆盖：tendency ← facing

**现象**：在没有按方向键的帧上，其它地方写进去的"意图方向"被重置为当前朝向；测试里预置 tendency 再跑一帧，tendency 变了，弹道/位移跟着变。

**6502 语义**：`NoDPad_Invalid`（无有效方向输入时的处理器）的第一件事就是 `LDA JeepFacingDirection,X / STA JeepDirectionTendency,X`——**每帧先把"倾向"同步成"朝向"，再处理本帧逻辑**。这是边沿输入模型的收尾：没有新输入，意图就等于朝向。

**翻译要点**：照抄顺序：同步发生在无输入处理器的入口，且覆盖本帧此前的任何写入；因此"先写 tendency、再调用移动/武器逻辑"的翻译顺序一定是错的。真实顺序是"处理输入 → tendency 归位到 facing → 用 tendency 算"。测试布置以 facing 为准（断言弹道方向钉 `JeepFacingDirection`，不要只钉 tendency）。

**实例与证据**：`Bank7.ASM:5638-5641`（NoDPad_Invalid 头两条）与武器发射段的相互作用（回查 task-3.7-report：发射帧的 tendency 会被 NoDPad 路径重置为 facing）；第三轮试玩修复中，火箭筒测试改为钉 `JeepFacingDirection` 后才稳定（回查 2026-07-22 修复记录·第三轮）。

### 12. CMP 相等仍 DEC 的停位

**现象**：位移/滚动"停在目标值上一格"——差一像素。断言写目标值不过，写目标值 -1 才过。

**6502 语义**：`LDA Cur / CMP Stop / BCC Skip / DEC Cur` 的骨架含义是"当前值 ≥ 停点就再走一格"；从停点出发（相等）`BCC` 不跳，于是还会再 DEC 一次，**终值 = 停点 - 1**。表作者通常把停点值写成"想要的位置 + 1"。

**翻译要点**：翻成 `if (cur >= stop) cur--;`（不是 `>`）；读停点表时把表值理解成"停位 + 1"；锚定测试写实际终值并在注释里写出推导（"表值 $C0 → 终值 $BF"），免得后人按直觉"修正"。

**实例与证据**：StageTransitionState3 的小吉普上行（`Bank7.ASM:999-1004`）：`LDA $0562 / CMP tblLittleJeepStopPoints,Y / BCC + / DEC $0562`，停点表在 :996-997（`db $C0,$A0,$80,$60,$40,$20`），L1 终值 $BF——ASM 原样实装并锚定（回查 task-6.3-report，"小吉普停位 quirk"）。

### 13. 分支落点静态解析：直跳越过 INC / 跨函数落点

**现象**：按行顺序读代码，某条指令"按逻辑应该执行"却没执行（或反之）；按顺序直译就多跑（或少跑）一段。

**6502 语义**：分支的目标由地址决定，不由版面决定。两种真实形态：**共享尾块**——两个例程共用 `RTS` 前的收尾段，回跳的分支越过中间的 `INC`；**跨函数落点**——前跳的分支越过一个 `RTS`，落进下一个例程体内的标签。匿名标签（`-`/`--`、`+`/`++`）按"最近"解析，靠得越近越容易误读。

**翻译要点**：动手前先把每个分支目标按地址解析成实际落点，再决定翻法：共享尾块提成独立函数（两个调用方都调它）；跨函数落点要么提成共享函数，要么按语义拆成"首帧/复帧"分支，注释里写明原落点地址。判定落点时用匿名标签的解析规则，不要数行。

**实例与证据**：`subWrite_A_ToGameControlState_SetScreenTimer_ClearTitleScreenState`（`Bank7.ASM:1140-1144`）末行 `BNE -` 回跳 :1134（`-: LDA #$00 / STA $1F / Label788: STA ControlSubState / RTS`），**越过** :1133 的 `INC GameControlState`；初版误复用 `subNextGameControlState`，Start 后 GCS 3→4→5 连跳、标题清除例程没执行（回查 task-2.6-report）。`Label474`（`Bank7.ASM:8347-8366`，`BNE ++` 在 :8352 与 :8389）前跨过 :8366 的 `RTS` 与 :8370-8401 整段，落点是 :8402；跨函数跳转在 C 侧建模为"首帧布置返 1 / 复帧爆炸+倒计时"（回查 task-4.11-report）。

### 14. 取反/移位结果只对"本帧"有效

**现象**：振荡或加速度被困在小范围里循环（某项目：爆炸溅射的火苗窝在爆点附近、振幅不再增长），单看每一帧都对，累积就错。

**6502 语义**：`$10/$11` 两个 scratch 存的是"生长后的幅度（**未取反**）"，A 里是"取反后的本帧速度"。流程是：幅度 `UB + 2` → 存 scratch → 方向翻转时取反（`EOR #$FF / CLC / ADC #$01`）并写回 UB → **用取反值积分一格** → 从 scratch 恢复 UB 为未取反幅度。取反值只服务"这一格"。

**翻译要点**：区分"本帧速度"与"下一帧的基数"：积分用前者，恢复用后者。把恢复值也写成取反值（或干脆漏掉恢复），下一帧就从负值继续加 2，振幅永远出不去。翻这类段要按指令顺序逐步标注"此刻 A / UB / scratch 各是什么"，不要做"数学等价"化简。

**实例与证据**：`JeepBazookaSplashState1`（`Bank7.ASM:6113-6151`）：:6119-6120 存未取反值到 `$10`、:6124-6126 取反、:6146 用 UB 积分位置、:6147-6150 `LDA $10 / STA ...UB` 恢复。初版误存取反值，溅射速度 UB 困在 ±6 小循环；修复后振荡逐帧递增（+4、-6、+8……），锚 `bazooka_splash_oscillation_grows`（回查 2026-07-22 修复记录·便利包）。

### 15. 反汇编勘误：注释只是提示

**现象**：注释给的地址/索引/bank 与代码实际使用的不一致；照注释翻译读到垃圾（生成头指针越界读到全 0），或在某些关卡整体错用另一张表。

**6502 语义**：反汇编是二手材料。权威是**ROM 字节 + 读表代码的操作数**——`LDA tbl,Y` 读哪张表，答案写在这条指令的机器码里，不在注释里。

**翻译要点**：三条纪律：以 ROM 与读表代码为准；把不一致**记下来**（报告、代码注释、登记 evidence，任一处但必须留痕）；不要静默采用其中一方。定位表地址最快的路径是回读引用它的那条指令的机器码（操作数是小端 dw），而不是搜注释里的地址。

**实例与证据**：`Bank7.ASM:6553` 的孤立注释 `;$F15D` 与 :6557 的 `tblF2LevelIndex` 相邻，容易被当成后面 `tblLevelObjectSpawnAddress`（:6630）的地址；回 ROM 定真值——`Label978` 序言里的 `LDA tblLevelObjectSpawnAddress,Y`（:6438）机器码为 `B9 E0 F1`（bank7 $F093，小端 $F1E0），ROM 实测 $F1E0 处正是六个 spawn 表指针（$85F4/$8941/$9064/$A151/$AA5C/$B128），初版按 $F15D 读被 `spawn_walk` 用例当场抓住（回查 task-2.8-report；该报告所记指令地址 $F081 略有偏差，实际指令在 $F093）。元精灵索引注释也有一例：`Bank1.ASM:1945-1946` 标 `;B4`，而 dw 表 `Bank1.ASM:1497` 标 `;B5`（`B4_UNKNOWN` 另有正确位置），以 dw 为准（回查 task-1.5-report）。同批勘误还包括：load 表实为 10 张（两个场景索引共享同一张）、元精灵组 2 物理顺序 ≠ 索引顺序（中间夹 garbage data）——所有冲突都按"回字节与 dw 定权威"处理并留档（回查 task-1.5-report）。

### 16. RLE 的极性与终止符因流而异

**现象**：两段"几乎一样"的 RLE（同一个 ROM、同一套 bit7 语义）不能换用解码器：把图案链的解码器套到 nametable 流上，终止判断差一个字节就整段错位。

**6502 语义**：控制字节的含义由例程的比较**顺序**决定。例程先 `CMP #$FF / BEQ 结束`，再 `BPL 重复分支`——于是"带 bit7（$80-$FE）"走字面拷贝、"不带 bit7（$00-$7E）"走重复，与"bit7 = 重复"的常见直觉**相反**；而 `$7F` 在 nametable 流里是"子段边界、回头读下一段段头"，在图案链里只是合法的重复计数 127。

**翻译要点**：每个 RLE 流配自己的解码器，不要抽公共函数"顺手统一"。终止符集合、极性、计数语义三件事都从该流例程的头几行读出，写进解码器注释与测试。判据很便宜：读 `CMP/BNE/BPL` 的顺序，再写分支。

**实例与证据**：图案链 `Bank7.ASM:358-363`（只认 $FF 终止，:360；极性见 :361 `BPL`）；nametable 流 `Bank7.ASM:2415-2418`（$FF 结束、$7F 子段边界两级终止）。两套流的计数 0 语义也不同（见条目 1）。口径与 `extraction-playbook.md` §4.2 一致（回查 task-10-report）。

### 17. 状态字节 bit7 兼作屏外标记

**现象**：状态机"跳错档"——对象在屏外时不更新、回到屏内又行为错乱；反查状态值时会看到 $86 这类"不存在的状态号"。

**6502 语义**：State 字节的 bit7 被借作"屏外"标记：在屏置 0（`AND #$7F`）、屏外置 1（`ORA #$80`）；所有分派入口都先 `AND #$7F` 取真实状态，因此 $86 会被当成状态 6 正常执行。这个标记还与"屏外消亡"检查级联：置起 bit7 之后紧邻的出屏检查可能把整个状态清 0。

**翻译要点**：状态比较一律先 `& 0x7F`；写状态时按原码决定是否保留 bit7（`(state & 0x80) | new`，或整写清 0——两者在 ASM 里都能找到，逐处置定）。测试布置要把"屏外/屏内"当成状态的一部分设置：构造"上移且未消亡"的场景需要精确坐标约束（否则会被出屏消亡提前打断），场景顺序也要与 ASM 一致——把"出屏消亡"放在最后。

**实例与证据**：`subUpdateSpritePositionForScrolling`（`Bank7.ASM:1679-1686`）的屏内 `AND #$7F` 与屏外 `ORA #$80`；L3 潜艇上移场景 State=$86（分派 `AND #$7F` 后照达 State6），出屏场景级联清 0（回查 task-4.8-report）。

## 结语

这 17 条共享一个形状：**反汇编读起来通顺，不等于语义一致**。计数 0、进位链、借位链、取反值、分支落点、隐式寄存器——每一条的错误版本都能通过"人眼读一遍"的审查，只有把指令逐条回读、把字节回查 ROM 才能定案。这也解释了为什么它们反复出现在保真优先级（SKILL.md 铁律四）最靠前的位置：帧节拍、生成与消亡条件、坐标与速度的定点行为，恰好是这些陷阱的高发区，而这些又是"大体对、细节错"最难在画面上立刻看出来的地方。

实用的记法是三句话：**遇循环先看减没减、看判的是减前还是减后**；**遇多字节运算先数 `CLC` 和进位**；**遇跳转先解析真实落点再动手**。三条都做到了，剩下的就是把每个修过的缺陷锚成一条测试（SKILL.md §7 的 L3），让下一次修改无法把它悄悄改回去。
